# Свой канбан вместо Trello и Jira: Wekan, перенос досок, права

>
  **Коротко.** Wekan (github.com/wekan/wekan) это канбан-доска под лицензией MIT, которую ставят на свой сервер: Docker, Snap, AppImage или архив. Карточки и колонки обновляются в реальном времени, интерфейс есть на русском. Доски переносятся из Trello, Jira, Asana, Notion и других источников, а после импорта Wekan показывает отчёт о потерях. Обратная сторона: релизы выходят по нескольку раз в день, за пять месяцев 2026 года опубликовано 85 уведомлений об уязвимостях, обновления и копии лежат на вас. Данные на 31.10.2026, я читал репозиторий и документацию, сам Wekan не запускал.

## Когда доски пора забирать из Trello и Jira

Команда сидит на Trello или Jira, платит за каждое место, а доски с клиентскими задачами лежат на чужих серверах. Свой канбан напрашивается, но переносить страшно: потеряются вложения, комментарии, исполнители. Эта статья про перенос и права. Если формат вам незнаком, начните с [разбора канбан-доски](/blog/kanban-doska-poryadok-v-zadachah-2026/). Про другую открытую замену Jira я писал в статье про [Plane](/blog/plane-upravlenie-proektami-2026/).

## Проект, лицензия и установка

Репозиторий wekan/wekan создан 21.01.2014, не архивирован, последний коммит от 31.10.2026. В файле LICENSE указан Lauri Ojansivu. Авторов 294, релизов 946. Версия v12.75 вышла 30.10.2026, а версии с 12.71 по 12.75 опубликованы за два дня. Лицензия MIT, она же в package.json. Платными в README названы хостинг SaaS на wekan.fi и коммерческая поддержка. Лицензии 68 зависимостей по одной я не читал.

Стек: Meteor 3.x. Для сборки из исходников README просит Node.js 26.x, заказчику собирать ничего не нужно. Есть образ ghcr.io/wekan/wekan, Snap с автообновлением, AppImage и архивы для Linux, Windows и macOS. База по умолчанию это FerretDB v1 с SQLite, отдельный сервер баз не нужен. FerretDB здесь собственный форк проекта под Apache-2.0. Поддерживаются также PostgreSQL и MongoDB с 6 по 9 версию.

README просит минимум 1 ГБ свободной памяти под Wekan и 4 ГБ всего на боевом сервере и предупреждает, что при заполненном диске база портится. Вложения хранятся на диске, в GridFS, S3 или MinIO, Azure Blob или Google Cloud. Русский перевод по файлу ru.i18n.json покрывает около 97 процентов строк, это мой подсчёт. Docker, Snap и бандл я не запускал, пишу по README.

## Перенос досок: что доезжает и что теряется

Список источников в README длинный, поэтому потери я читал по четырём основным, а в код импорта Trello заглянул.

Trello принимается JSON одной доски, zip со многими досками и вложениями или напрямую из API по ключу и токену. Списки, карточки, метки, чек-листы, комментарии с автором и датой, пользовательские поля и обложки переезжают. В JSON-выгрузке Trello самих файлов нет, вложения придётся брать через zip или API-ключ. Данные Power-Up не переносятся, стартовая дата карточки не читается, голоса несопоставленных участников пропадают.

Jira читается из JSON поиска REST API: статусы становятся списками, задачи карточками, переезжают подзадачи, эпики и спринты. Из исполнителей читается только первый. Файл больше 4 миллионов значений Wekan отвергнет, его придётся делить. В Asana исполнители не становятся участниками карточек. Из Notion не переносятся связи между страницами, вложенные подстраницы, картинки и файлы.

Людей из файла Wekan по умолчанию превращает в пользователей-заглушек, которые не могут войти, потом администратор сопоставляет их с живыми. После импорта виден отчёт о потерях, он же хранится в Admin Panel, Problems, Recovery. Сверку я всё равно делал бы вручную: число карточек, вложений и участников по каждой доске. Документ Format-Coverage в репозитории сам помечен Implementation in progress, аудит от 05.09.2026. Импорт я не запускал.

## Права, вход и безопасность

Ролей на доске девять: администратор, обычный участник, только комментарии, исполнитель (двигает карточки, назначает себя и комментирует), только чтение, без комментариев и три варианта «видит только назначенные карточки». Вход через LDAP, SAML и OAuth2 есть по README, в уведомлениях встречаются ещё OIDC и CAS.

В списке уведомлений репозитория 85 опубликованных записей, все с 30.05.2026 по 30.10.2026: 9 критических, 30 высоких, 43 средние, 3 низкие. У 19 есть номер CVE, у всех указана исправленная версия. В базе NVD по слову wekan я нашёл 61 запись, 51 из них за 2026 год.

Среди критических вход через LDAP принимал пустой пароль в одном из режимов (версии от 12.07, исправлено в 12.08), метод importBoard работал без авторизации (до 11.09, исправлено в 11.10), загрузка вложений давала записать произвольный файл (до 11.64). Много записей про обход ролей: участник «только комментарии» создавал карточки через импорт ICS, читатель создавал дорожки. Запись от 30.10.2026 касается импорта из zip с идентификаторами чужой доски (исправлено в 12.69).

Старая версия опасна, README признаёт это: поддерживается только последняя. Мой минимум для такого сервера: обратный прокси с HTTPS, админка по VPN или белому списку, регламент обновлений и проверка входа после каждого. Парольная политика, обязательная двухфакторная аутентификация и журнал действий администраторов в CHANGELOG значатся в разделе Upcoming, в v12.75 их ещё нет.

## Где Wekan слабее платных сервисов

- Поддержка. Публичная идёт только через issues на GitHub, закрытая платная продаётся на wekan.fi. Гарантии ответа у самостоятельной установки нет.

- Обновления. Релизы выходят по нескольку раз в день, и ставить последний придётся вам. В облачном сервисе это делает поставщик.

- REST API. Документация сама пишет, что он пока не полный, а среди уведомлений много записей про неверные проверки прав в REST. Интеграции придётся проверять.

- Копии. README требует копию базы минимум раз в сутки и предупреждает, что часть сбоев чинится ручной правкой базы. Плановые и непрерывные копии в панели есть, восстановление я не проверял.

Удобен ли интерфейс команде из двадцати человек, я не проверял, это покажет пилот на живой доске.

## Что можно сделать уже сейчас

Первое. Выгрузите одну живую доску из Trello в JSON или задачи проекта из Jira с параметрами fields=*all и expand=names,schema. Посчитайте карточки, вложения и исполнителей для сверки.

Второе. Поднимите Wekan из docker-compose.yml на тестовом сервере с 4 ГБ памяти, импортируйте эту доску, сравните с эталоном и прочитайте отчёт о потерях целиком.

Третье. Заведите тестовых пользователей на разных ролях и проверьте, что читатель и участник «только назначенные» видят ровно положенное.

Четвёртое. Остановите сервис, скопируйте каталог files, разверните копию на второй машине и откройте доску.

Установку, обновления, импорт досок с проверкой, права и копии я делаю в рамках [автоматизации бизнес-процессов](/services/business-automation/) и [open-source решений под ключ](/predlozheniya/open-source-pod-klyuch/). Регулярные обновления и контроль копий можно оформить как [сопровождение](/services/devops/).

## Частые вопросы

### Нужен ли отдельный сервер баз данных?

По умолчанию нет, FerretDB с SQLite идёт в поставке. MongoDB или PostgreSQL подключаются по желанию.

### Заменит ли Wekan Jira целиком?

В README есть Scrum-режим со спринтами, бэклогом и burndown, диаграмма Ганта и правила наподобие Trello Butler. Хватит ли этого вашему процессу, покажет пилот, эти режимы я не запускал.

### Можно ли открыть Wekan в интернет без VPN?

Можно, но обновлять тогда придётся в день выхода релиза. Если на досках нет внешних людей, я бы ограничил доступ по VPN или белому списку адресов.

## Коротко о главном

Wekan подходит команде, которая готова обновлять сервер каждую неделю и проверять копии. Импорт из Trello и Jira переносит основное и сам перечисляет потери, но вложения, исполнителей и Power-Up нужно сверять руками. Права по доскам настраиваются девятью ролями.

Хотите перенести доски из Trello или Jira на свой сервер? Напишите мне в Telegram кодовое слово «КАНБАН». Поставлю Wekan на стенд, импортирую одну вашу доску, покажу отчёт о потерях и права по ролям до того, как вы переведёте команду.
