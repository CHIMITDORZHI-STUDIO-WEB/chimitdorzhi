# ИИ-помощники команды учатся друг у друга: Tencent TeamAI CLI

>
  **Коротко.** Tencent выложила в открытый доступ TeamAI CLI под лицензией MIT. Инструмент складывает навыки, правила, хуки и настройки MCP для ИИ-агентов команды в один git-репозиторий и раздаёт всем участникам. Работает с Claude Code, Codex, Cursor, CodeBuddy, OpenCode и ещё шестью агентами. Изменения идут через пуш и запрос на слияние с ревью, а раз в неделю команда получает дайджест, где видно расход токенов по людям. Для техкоманды из трёх и более разработчиков это способ перестать жить с десятью разными настройками ИИ-помощника.

## Что выпустила Tencent

Каждый разработчик настраивает ИИ-помощника под себя. У одного есть хороший набор правил для кода, у второго отлаженный навык для разбора логов, у третьего подключены нужные MCP-серверы. У остальных ничего этого нет, и узнают они о находках только случайно, в курилке.

TeamAI CLI решает именно это. Репозиторий на GitHub называется [Tencent/teamai-cli](https://github.com/Tencent/teamai-cli), описание: «Make Every Team AI Native». Создан 27 апреля 2026 года, на момент проверки (1 октября 2026) у него около 5,1 тысячи звёзд, 386 форков, 39 открытых задач, последний пуш в основную ветку сделан в тот же день. Установка через npm, нужен Node.js 20 или новее и git.

## Как это работает

Администратор создаёт общий репозиторий и кладёт туда навыки (папки с файлом SKILL.md), правила в виде markdown, документацию, переменные окружения, хуки и описания MCP-серверов. Каждый участник один раз выполняет teamai init с адресом репозитория. Дальше при старте каждой сессии с ИИ-помощником подтягивается свежая версия, вручную это делается командой teamai pull.

Хочешь добавить своё, делаешь teamai push. Инструмент создаёт запрос на слияние, коллеги смотрят, после принятия изменение уходит всем. Репозиторий может лежать на GitHub, GitLab или на вашем сервере. Можно разделить ресурсы по ролям и проектам: бэкенду свои навыки, фронтенду свои, общие правила у всех.

Сам инструмент кода не пишет и модели не содержит. Он только раскладывает файлы по папкам тех агентов, которые стоят на машине участника. Поддерживаются 11 агентов: Claude Code, Codex, Cursor, CodeBuddy, WorkBuddy, OpenCode, OpenClaw, Hermes, DeepSeek Harness, Qoder и ZCode. Объём получаемого у них разный: например, DeepSeek Harness получает только навыки и документы.

## Хук, который учит команду

По хуку завершения сессии TeamAI оценивает её по «трению»: вы прерывали агента, поправляли его, отклоняли вызов инструмента, он повторял неудачные попытки. Спокойная длинная сессия без проблем не считается. Если трения набралось достаточно, агент предлагает записать вывод в командный репозиторий, при этом одна сессия предлагается не больше одного раза. Вывод попадает в базу знаний команды через ту же схему с ревью.

Получается цикл. Сотрудник наступил на грабли, агент это заметил, правило появилось у всех, и завтра на те же грабли наступает уже не вся команда.

## Расход токенов виден

Команда teamai digest собирает недельный дайджест. В нём сводка по сессиям, количество реплик, суммарный расход токенов по команде и рейтинг по людям. Токены считаются для Claude Code, CodeBuddy и Codex. Метрики хранят только числа: тексты запросов и ответов остаются на машине автора.

В панели управления и в дайджесте есть ещё оценка стоимости, но с оговоркой самого проекта: это пересчёт по публичным прайсам для распознанных моделей Claude, а не счёт и не стоимость подписки. Для динамики сгодится, для бухгалтерии нет.

## Чего пока нельзя и где подводные камни

Слой раздачи ресурсов (навыки, правила, хуки, MCP) заявлен как готовый. Слои «контекст» и «улучшение», то есть база знаний, сессии, дайджест и панель, в README помечены бета-версией. Рассчитывать на них как на продакшен-отчётность рано.

Cursor не отдаёт данные транскрипта, поэтому токены по нему показываются нулями. Если половина команды сидит в нём, дайджест будет неполным. Всё работает на локальных машинах: пока человек не запустил сессию, обновление до него не дойдёт.

Секреты в репозиторий класть нельзя. Файл переменных окружения хранит значения открытым текстом, для секретов в проекте есть отдельное объявление без значения, а сами ключи остаются у человека. Общий репозиторий становится точкой доверия. Вредное правило, прошедшее ревью по невнимательности, разойдётся по всей команде. Без дисциплины ревью инструмент превращается в массовую раздачу чужих ошибок.

Ещё одна оговорка. GitHub в метаданных показывает лицензию как нераспознанную, хотя в файле LICENSE и в README стоит стандартный текст MIT без дополнительных условий. Перед внедрением в коммерческую команду юристу стоит всё же взглянуть на файл самому.

## Что можно сделать уже сейчас

**Команда разработки от 3 до 15 человек.** Собираем общий репозиторий: единые правила оформления кода, навыки для типовых задач (ревью, миграции, тесты), список подключённых MCP-серверов. О том, что такое MCP и зачем он нужен, мы писали в [отдельной статье](/blog/mcp-model-context-protocol-2026/). Новый человек получает рабочее окружение одной командой, а не неделей переписки.

**Правила безопасности.** В общий конфиг уходит список того, что агенту нельзя: трогать боевую базу, читать файлы с ключами, ходить на сторонние адреса, пушить в основную ветку без ревью. Принципы здесь те же, что в материале про [безопасное использование ИИ в компании](/blog/bezopasnyy-ii-v-kompanii-2026/), только теперь они лежат в репозитории и действуют на всех одинаково.

**Контроль расходов.** Раз в неделю смотрим дайджест: кто и на каких задачах сжигает токены, где дорогая модель используется для работы, с которой справилась бы дешёвая. Как переводить такие задачи на модели подешевле, разобрано в статье [про маршрутизацию моделей](/blog/kak-udeshevit-ii-agenta-marshrutizaciya-modeley-2026/).

**Обучение.** Живые примеры из реальных сессий команды становятся навыками и разборами. Это лучше любой презентации, потому что относится к вашему коду, а не к абстрактному проекту.

Всё это входит в [внедрение ИИ-агентов](/services/ai-agents/) и, если у вас нет технического руководителя, в [CTO как сервис](/services/cto-as-a-service/). Ориентиры по стоимости есть в [прайсе](/ceny/).

## Частые вопросы

### Это только для Claude Code?

Нет. Заявлено 11 агентов, среди них Claude Code, Codex, Cursor, CodeBuddy и OpenCode. Но функции у них отличаются, полный набор получают не все. Перед внедрением стоит свериться с таблицей совместимости в документации под тех агентов, которыми пользуется ваша команда.

### Можно ли использовать в коммерческом проекте?

Лицензия MIT разрешает коммерческое использование, изменение и распространение. Отдельное внимание стоит уделить содержимому: что именно ваши правила и навыки раскрывают о вашем коде и инфраструктуре, особенно если репозиторий лежит на внешнем сервисе.

### Подойдёт ли это, если разработчик у меня один?

Пользы мало. Инструмент решает задачу согласованности между людьми. Одному разработчику хватит собственных файлов настроек и хорошо написанных навыков.

## Коротко о главном

TeamAI CLI превращает настройки ИИ-помощников из личного дела каждого разработчика в общий репозиторий с ревью: правила, навыки, хуки и MCP раздаются командой, а недельный дайджест показывает расход токенов. Часть функций ещё в бете, секреты в репозиторий не кладутся, а ревью нужно делать всерьёз. Он нужен техническим командам, без разработчиков в штате он бесполезен.
