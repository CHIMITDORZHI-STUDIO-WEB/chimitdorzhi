# Understand Anything: граф чужого кода, по которому можно спрашивать

>
  **Коротко.** Understand Anything (репозиторий Egonex-AI/Understand-Anything, лицензия MIT) это плагин для ИИ-помощника по программированию. Он читает проект, строит граф из файлов, функций и связей, сохраняет в JSON-файл и открывает локальную страницу, где по графу можно ходить и задавать ему вопросы. Для владельца с чужим кодом это быстрый ориентир. Условие одно: код читает модель вашего помощника, то есть чужое облако, если не подключить локальную. Граф помогает искать и не заменяет чтение кода. Языка 1С в списке поддерживаемых нет.

## Автор ушёл, а вопросы остались

Сайт или бота годами вела одна студия, доработки 1С писал один человек, регламенты лежат в десяти папках. Человек ушёл. Новому исполнителю нужно время, чтобы понять, что где лежит, и это время оплачивает заказчик. Про доступы и репозиторий я писал в статье [как не стать заложником подрядчика](/blog/kak-ne-stat-zalozhnikom-podryadchika-dostupy-repozitoriy-dokumentaciya-2026/), про схему в формате Mermaid в разборе [oh-my-mermaid](/blog/oh-my-mermaid-shemy-arhitektury-po-kodu-proekta-2026/). Здесь другой инструмент: граф, по которому можно ходить мышкой и задавать вопросы словами.

О Understand Anything 16 октября 2026 рассказал канал GitHub Community. Саму публикацию я не открывал, всё ниже взято из репозитория.

## Что это за проект и что я проверил

Проверял 17.10.2026. Репозиторий [Egonex-AI/Understand-Anything](https://github.com/Egonex-AI/Understand-Anything) раньше жил под аккаунтом Lum1104, старый адрес перенаправляет на новый. Описание на GitHub совпадает с постом: работает с Claude Code, Codex, Cursor, Copilot, Gemini CLI и другими. Файл LICENSE содержит текст MIT, правообладатели Yuxiang Lin и Infinite Universe, Inc. Репозиторий создан 15 марта 2026 года, не архивирован, около 86,6 тысячи звёзд и 7,3 тысячи форков. В основной ветке порядка 858 коммитов, последний от 12 октября (правка описания домашней страницы), последний релиз v2.9.0 вышел 10 июля.

Устроен он как плагин для Claude Code. Для остальных помощников README даёт установщик (Codex, OpenCode, Gemini CLI, VS Code с Copilot и другие), а Cursor подхватывает плагин из клонированного репозитория.

## Как строится граф и откуда берутся связи

Команда /understand запускает цепочку из пяти агентов. Сканер находит файлы, анализаторы разбирают их пачками по 20-30 штук, следующие агенты раскладывают проект по слоям (API, сервисы, данные, интерфейс) и собирают тур по проекту. Итог лежит в файле .ua/knowledge-graph.json в корне проекта.

Связи определяются двумя способами. Импорты, вызовы, наследование и определения достаёт tree-sitter, обычный разбор синтаксиса без модели: на тех же файлах он даёт те же связи. Смысл (что файл делает, к какому слою относится, как назвать шаг процесса) пишет модель. Разборщики кода есть для TypeScript и JavaScript, Python, Go, Rust, Java, Ruby, PHP, C#, C и C++, Swift, Kotlin, Scala и Dart. Кроме них в плагине 42 описания языков и форматов, среди них Markdown, YAML, SQL, Dockerfile и OpenAPI.

Команда /understand-dashboard открывает страницу на 127.0.0.1: граф по слоям, поиск по имени и по смыслу, карточка узла с кодом и пояснением. Команда /understand-domain добавляет вид «домены, потоки, шаги», то есть как код ложится на бизнес-процессы. Вопросы задаются командой /understand-chat: агент находит в файле графа нужные узлы и связи и отвечает по ним. Отвечает опять модель, граф служит ей справочником. Граф знаний по документам, а не по коду, я разбирал в статье про [GraphRAG](/blog/graphrag-graf-znaniy-vmesto-obychnoy-bazy-znaniy-kogda-okupaetsya-2026/).

## Куда уходит код

Своей модели у плагина нет. Файлы читает ваш помощник и отправляет их своему провайдеру: Claude Code работает с Anthropic, Codex обычно с OpenAI, Cursor с выбранной в нём облачной моделью. Для закрытого проекта заказчика это третья сторона, и договор со студией мог её не предусматривать. Для приватных проектов README советует подключить локальную модель через Ollama. Какого качества граф получится на такой модели, я не проверял.

Из кода плагина видно два нюанса. Список исключений по умолчанию прячет node_modules, сборки, картинки, PDF и lock-файлы, а .env в нём нет. Для .env есть отдельный разборщик, он берёт только имена переменных, но читает ли файл целиком агент-анализатор, я не проверял. Закрыть лишнее позволяют файл .understandignore и параметр --exclude. Я исключаю .env, выгрузки клиентов и бэкапы до первого запуска, подробнее о том, что нельзя показывать ИИ, в статье про [DevProjex](/blog/devprojex-bezopasnyy-kontekst-koda-dlya-ii-bez-sekretov-i-pd-2026/).

Второй нюанс приятный. Готовый граф можно смотреть без модели: просмотрщик (запускается через npx, нужен Node.js) читает файлы с диска и, по README, ничего никуда не отправляет.

## Где граф ошибётся и чего не покроет

Граф это ориентир. Структурные связи точны настолько, насколько точен разбор синтаксиса. Описания, слои и тур пишет модель, и она может назвать модуль не тем, увидеть связь, которой нет, или пропустить вызов, спрятанный в конфигурации. По умолчанию проверка внутри плагина сверяет целостность графа (связи ведут на существующие узлы), полный разбор моделью включается флагом --review. Я сверяю с исходниками хотя бы десяток случайных узлов.

Языка 1С (BSL) в списке нет. Для доработок 1С ожидайте пустую или поверхностную карту, как плагин поведёт себя на таких файлах, я не проверял. Word в списке типов нет, PDF исключён по умолчанию. Всё, что живёт вне репозитория (сервер, расписание задач, кабинеты платёжных систем, чужие сервисы), в граф не попадёт.

По токенам README честен: первый запуск разбирает весь проект и на большом может потратить много, советуют подписку или локальную модель, повторные запуски идут по изменённым файлам. Чисел и предела по размеру проекта я не нашёл, для огромных репозиториев предлагают указать подпапку. Актуальность держит параметр --auto-update (хук после коммита), а /understand-chat перед ответом сверяет коммит графа с репозиторием и предупреждает об отставании. Сам плагин на чужом проекте я не запускал.

## Что можно сделать уже сейчас

- Принимаете проект: попросите студию приложить к акту передачи сгенерированный граф с датой и коммитом, на котором он построен. README советует хранить папку .ua в репозитории, кроме intermediate и diff-overlay.json.

- Хотите понять, что купили: закажите разбор на копии без секретов. Я делаю его в рамках [технического аудита](/services/it-audit/): граф, проверка по коду и карта системы на пару страниц простым языком, с пометкой, что граф не видит.

- Код закрытый: сначала решите, какая модель его прочитает, облачная с согласия владельца или локальная.

- Своя команда: включите --auto-update и дайте менеджерам просмотрщик, пусть открывают страницу сами, а не просят разработчика объяснять.

## Частые вопросы

### Нужна ли отдельная подписка?

У плагина своей модели нет, расходуются лимиты вашего помощника или локальная модель. Платных тарифов самого плагина в README я не нашёл, лицензия MIT.

### Можно ли смотреть граф, не ставя помощника?

Да, если граф уже построен и лежит в папке .ua. Нужен только Node.js, ключ и модель не требуются.

### Заменит ли это передачу проекта?

Граф покрывает то, что лежит в файлах. Доступы, домен, сервер и подписки остаются в передаче проекта, их порядок я описывал в разборе [аудита чужого бота и сайта за два часа](/blog/chuzhoy-bot-ili-sayt-ne-rabotaet-audit-za-dva-chasa-2026/).

## Коротко о главном

Understand Anything даёт то, чего обычно не хватает после ухода автора: карту, по которой можно ходить, и ответы на вопросы с опорой на файлы. Цена вопроса: код читает модель помощника, а описания в графе нужно сверять с исходниками.
