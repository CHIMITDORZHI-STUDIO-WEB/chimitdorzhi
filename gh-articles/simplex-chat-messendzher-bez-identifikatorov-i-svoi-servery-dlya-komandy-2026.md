# SimpleX: чат без номера и логина и свои серверы для команды

>
  **Коротко.** SimpleX (репозиторий simplex-chat/simplex-chat, лицензия AGPL-3.0, около 19,6 тысячи звёзд) это мессенджер без номера телефона, логина и случайного ID: люди соединяются по одноразовой ссылке или QR-коду. История лежит на устройствах. Можно поднять свои серверы: SMP для сообщений и XFTP для файлов. Резервной копии по умолчанию нет, для массового клиента он неудобен. Я проект не запускал, текст написан по документации и коду. Правовой статус в РФ уточняйте у юриста.

## Чат, где о людях нечего узнавать

Консультант обсуждает с клиентом сделку, юрист пишет директору про спор с партнёром. В привычном мессенджере у обоих есть номер или логин, и сервис видит, кто с кем связан. Текст можно зашифровать, а сеть знакомств остаётся у сервиса.

Корпоративные мессенджеры на своём сервере я уже разбирал: [Matrix и Element](/blog/matrix-element-korporativnyy-messenger-2026/) и [Mattermost](/blog/mattermost-korporativnyy-messenger-2026/). Там у каждого сотрудника есть учётная запись, а у администратора список людей и комнат. SimpleX устроен по-другому: идентификаторов нет совсем, и серверы можно держать свои.

## Что это за проект и что я проверил

Проверял 19.10.2026 по GitHub и документации в репозитории. Адрес: [github.com/simplex-chat/simplex-chat](https://github.com/simplex-chat/simplex-chat). Файл LICENSE содержит текст GNU AGPL версии 3. Название и логотип лицензией не покрыты. Репозиторий создан в декабре 2019 года, не архивирован, около 19,6 тысячи звёзд, последнее обновление 18 октября 2026. Последний стабильный релиз v7.0.3 вышел 26 сентября, релиз 7.0.4 и бета 7.1.0 от 3 октября помечены как предварительные.

Разработчик: компания SimpleX Chat Ltd, основатель Евгений. У него больше всего коммитов (3437 по данным API), следом ещё несколько человек. Ядро написано на Haskell. Документация только на английском, интерфейс переводится на русский через Weblate, полноту перевода не проверял.

Приложения по README: Android (Google Play, F-Droid, APK), iOS (App Store, TestFlight), десктоп для Windows, macOS и Linux, консольный клиент. Страницы магазинов я не открывал. Про RuStore в документации ничего нет, наличие там не подтверждено.

## Что знают серверы

Учётных записей нет, поэтому серверу нечего хранить о человеке. Каждое соединение двух людей состоит из односторонних очередей сообщений, и адреса очередей у каждой пары свои. По README серверы не ведут записей о пользователях, не общаются друг с другом и удаляют сообщение после доставки. Реализация SMP-сервера держит сообщения в памяти, на диск пишутся только записи об очередях.

Чего сервер не скрывает: IP-адрес подключающегося устройства. Предустановленные серверы, по политике, IP не логируют. В модели угроз протокола написано, что наблюдатель за трафиком отправителей и получателей может сопоставить их. Приватность здесь не равна анонимности, и обещать клиентам второе нельзя.

## Свои серверы SMP и XFTP

Нужны VPS, домен и базовые навыки Linux. Официально поддерживается только Ubuntu. Для SMP открывают порт 5223, для страницы сервера и сертификатов порты 80 и 443. XFTP использует 443 и требует задать квоту на диск. Есть образы Docker и установочный скрипт. В инструкции для Linode сказано, что для SMP хватает машины с 1 ГБ памяти. Ресурсы для XFTP зависят от квоты, цифр не нашёл.

Команда smp-server init -n домен создаёт ключи и сертификаты, отпечаток входит в адрес сервера. Ключ корневого сертификата документация советует удалить с сервера и хранить отдельно. Останавливать сервер при включённом журнале нужно сигналом SIGINT, иначе недоставленные сообщения не сохранятся. Пароль ограничивает, кто может заводить очереди на вашем сервере. Писать вам смогут и без пароля.

Свой сервер добавляется в настройках сети и действует для новых контактов, старые переносятся вручную по одному. Инструкция по XFTP датирована июлем 2023, файлы там хранятся ограниченное время (указано 48 часов), сверьте с актуальной версией. На iOS уведомления идут через серверы SimpleX Chat Ltd даже при своих серверах, это сказано в политике. AGPL требует публиковать изменения, если вы правите код сервера.

## Группы, бизнес-адрес и аудиты

Группы одноранговые. По документации, добавление участника требует N новых соединений, поэтому для большой аудитории они не подходят. Жёсткого лимита участников я не нашёл, для десятка человек схема должна работать, но это моя оценка. Ролей пять: владелец, админ, модератор, участник и наблюдатель. Для клиентов с версии 6.2 есть бизнес-адрес: каждый обратившийся получает отдельный чат, куда можно добавлять сотрудников.

Независимых аудитов два, оба сделала Trail of Bits. В октябре 2022 двое инженеров неделю смотрели библиотеку simplexmq: 2 средних и 2 низких замечания, три исправлены в версии 4.2. Приложения и сервер push-уведомлений в охват не вошли. В июле 2024 прошёл обзор криптографического дизайна протоколов: 3 средних, 1 низкое и 3 информационных замечания, критичных нет. Более свежего отчёта в README и документации я не нашёл.

## Где SimpleX не подойдёт

Резервной копии по умолчанию нет. Переписка и контакты живут только на устройстве: потеряли телефон без экспорта, потеряли всё. Забытый пароль базы не восстановить. Переносить данные нужно встроенным способом приложения.

Один профиль на нескольких устройствах не поддерживается. Мобильный профиль подключается к десктопу только в одной локальной сети. Найти человека по номеру нельзя, контакт появляется после одноразовой ссылки или QR-кода. Звать клиентов вручную можно для десятка людей, для тысячи это неудобно.

Разработчики сами называют платформу относительно ранней, серверы по умолчанию работают без гарантий доступности, в репозитории около 1300 открытых задач. Каталога сотрудников и администрирования учёток нет: заменой привычного рабочего чата это не станет.

## Частые вопросы

### Видит ли оператор сервера, с кем я переписываюсь?

По README, серверы не имеют записей о пользователях и не знают, как связаны очереди разных людей. IP-адрес они видеть могут, а наблюдатель за сетью способен сопоставить отправителя и получателя, это описано в модели угроз.

### Что будет, если сотрудник потерял телефон?

Данные хранятся только на устройстве. Без экспорта восстановить переписку нельзя, контакты придётся соединять заново по новым ссылкам.

### Можно ли переписываться с клиентами?

Для небольшого числа клиентов подойдёт бизнес-адрес, но клиент должен установить SimpleX. Для массовой переписки я бы выбрал другой канал.

## Коротко о главном

SimpleX под AGPL-3.0 даёт закрытый канал без номеров и логинов и позволяет держать свои SMP и XFTP серверы. Цена такого устройства: нет резервной копии, нет поиска по номеру, группы небольшие, а IP-адрес остаётся видимым.
