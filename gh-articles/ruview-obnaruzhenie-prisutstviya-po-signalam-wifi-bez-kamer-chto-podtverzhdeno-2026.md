# RuView: присутствие по Wi-Fi без камер, что подтверждено

>
  **Коротко.** RuView (репозиторий ruvnet/RuView, лицензия MIT, создан 07.06.2025, около 99 тысяч звёзд на 22.10.2026) обещает по сигналам Wi-Fi находить людей в комнате, считать дыхание и пульс, без камер. Обычный роутер для этого не годится: нужны платы ESP32-S3 с особой прошивкой или исследовательские сетевые карты. Авторы называют проект бетой и пишут, что это не медицинское изделие. Точность в реальной комнате в README измерена слабо, а в трекере есть воспроизведение, где определение присутствия дало результат на уровне случайного. Я проект не запускал. Как предмет для пилота он интересен, как готовая система нет.

## Узнать, есть ли кто в номере, и не ставить камеру

Гостинице нужно знать, занят ли номер. Клинике нужно видеть, свободен ли кабинет. Магазину нужно считать людей в зале. Камера в номере или кабинете означает согласия и жалобы, поэтому «Wi-Fi вместо камеры» звучит привлекательно. Описание RuView обещает пространственный анализ в реальном времени, контроль жизненных показателей и обнаружение присутствия «без единого пикселя видео».

Про камеры с ИИ и их пределы у меня есть [отдельный разбор](/blog/kamery-videonablyudeniya-s-ii-dlya-biznesa-2026/), а про то, почему Wi-Fi-счётчики по MAC-адресам врут, [вот этот](/blog/wifi-analitika-mac-ne-rabotaet-2026/). RuView работает по другому принципу: он анализирует, как тела людей искажают радиосигнал между платами, телефоны ему не нужны.

## Что за проект и что я проверил

Проверял 22.10.2026 по [GitHub](https://github.com/ruvnet/RuView) и тексту README. Владелец ruvnet, в коммитах он подписан rUv. Репозиторий не архивирован, звёзд около 99 тысяч за шестнадцать месяцев. Это говорит об интересе, качество звёзды не измеряют. Файл [LICENSE](https://github.com/ruvnet/RuView/blob/main/LICENSE) содержит текст MIT. В ветке main 1544 коммита, последний от 13.10.2026, пуши были и 21.10. Около 1195 коммитов у владельца, 110 записаны на учётную запись claude, ответы мейнтейнера в трекере подписаны «Generated by Claude Code». Теги с v3258 по v3263 вышли 13.10 за сорок минут, номер версии зрелости не показывает. Код на Rust, Python, TypeScript и C, документация на английском.

## На каком железе это работает

Опора здесь CSI, детальные данные о радиоканале, которые обычные драйверы не отдают. README называет подходящим железом платы ESP32-S3 (около 9 долларов за узел, набор от 3 до 6 плат с роутером около 54 долларов), ESP32-C6 как исследовательский узел и карты Intel 5300 или Atheros AR9580. ESP32-C3 и оригинальный ESP32 не поддерживаются. Ноутбук по README даёт только грубое присутствие по уровню сигнала. Для роутеров на чипах MediaTek есть экспериментальный путь, данные там помечены «physical-unvalidated», без проверки качества. Docker-образ работает на имитированных данных, годится только посмотреть интерфейс. Прошивку на платы заливаете сами, для лучшего результата README советует две и больше плат.

## Что заявлено и что показано

Вверху README стоят присутствие сквозь стены, счёт людей, дыхание, пульс, падения, сон и 17 точек позы. Ниже тот же файл разбирает модели по зрелости, и картина скромнее.

Присутствие. README называет проверенной цифру 82,3%. По разбору пользователя в [issue 1440](https://github.com/ruvnet/RuView/issues/1440) это метрика обучения кодировщика, где случайный кодировщик набирает 69,6%, а точность присутствия она не измеряет. Он записал на трёх платах 5,9 часа с человеком и пустую комнату, после поправки на время суток получил AUC около 0,58, почти случайное. В [issue 1521](https://github.com/ruvnet/RuView/issues/1521) показан расчёт: опубликованная голова присутствия не может выдать «никого нет». Мейнтейнер согласился и написал, что нужны переобученные веса, а надёжным путём назвал калибровку под каждую комнату. Issue открыто, в README эта модель всё ещё в разделе «Real & validated».

Дыхание и пульс. Руководство пишет, что оценки несут пометку «нет эталонного измерения» и показывают работу тракта, точность они не доказывают. Условия: человек почти неподвижен, до точки доступа от 3 до 5 метров. В таблице применений стоят «дыхание ±1 в минуту», «точность присутствия выше 95%», «тревога при падении меньше 2 с», рядом измерений нет. Для падений в одной таблице указано меньше 2 с, в другой 200 мс.

Поза. На живой плате 3,0% PCK@20 при цели 35%, рабочий код пока заглушка с нулевой уверенностью. Цифра 82,69% относится к отдельной академической выборке MM-Fi. Просьбу показать таблицу доказательств ([issue 2150](https://github.com/ruvnet/RuView/issues/2150), 04.10.2026) оставили без таблицы, автору предложили оформить её самому.

## Приватность и закон

README пишет, что без камер установка по замыслу обходит правила о видео. Руководство по Home Assistant говорит осторожнее: режим --privacy-mode прячет пульс, дыхание и позу, но сам не делает установку соответствующей закону, а часть состояний, например «спит», выводится из показателей здоровья.

По [152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/) (редакция на consultant.ru от 26.07.2026, страница отмечает и не вступившие в силу поправки) персональные данные это любая информация, относящаяся к прямо или косвенно определяемому человеку. Сведения о состоянии здоровья отнесены к специальным категориям (ст. 10). Биометрия по ч. 1 ст. 11 это сведения о физиологических особенностях, которые оператор использует для установления личности, нужно письменное согласие. Счётчик людей, не устанавливающий личность, под эту часть не подпадает. Пульс гостя в конкретном номере уже привязан к человеку. Как квалифицировать вашу установку, уточняйте у юриста. Про согласия: [предложение по биометрии](/predlozheniya/biometriya-152fz-soglasiya/).

## Что важно учесть

Основной автор один, и README продвигает коммерческую плату Cognitum Seed (около 140 долларов) и партнёрскую программу с комиссией 25%. Статус «Beta software», API и прошивка могут меняться. README прямо пишет: это исследовательские и прототипные применения, не медицинские изделия и не системы безопасности. Медицинских выводов и тревог для людей на этом строить нельзя.

Безопасность. Поток от плат идёт по UDP без аутентификации, нужен список разрешённых адресов. Просмотрщик на порту 9880 без авторизации и TLS слушает по умолчанию только локальный адрес. Держите систему в отдельной сети. Доступность GitHub, Hugging Face и закупки плат из России не проверял, уточняйте.

## Что можно сделать уже сейчас

Сначала решите, что нужно. Если «есть ли кто в комнате», сравните с радаром mmWave или датчиком двери на [ESPHome](/blog/esphome-zigbee-datchiki-2026/): они дешевле в проверке.

Дальше пилот на одной комнате: две-три платы ESP32-S3, 14 суток, журнал фактов по датчику двери или ручной отметке. Пустую комнату записывайте в то же время суток, что и занятую, так делал автор issue 1440. Порог заранее. Условный пример: если за 14 суток система путает пустой номер с занятым чаще, чем в одной проверке из десяти, внедрять рано (допущение моё).

Пульс, дыхание и позу не включайте. Собрать пилот и отчёт по замерам могу в рамках [умного дома и IoT под нишу](/predlozheniya/umnyy-dom-iot-produkt/).

## Частые вопросы

### Подойдёт ли обычный роутер?

По README нет. Полные данные CSI дают платы ESP32-S3 или исследовательские карты, ноутбук даёт грубое присутствие.

### Можно ли следить за дыханием ребёнка или пациента?

Нет. README называет проект исследовательским, не медицинским изделием, а оценки пульса и дыхания помечены как непроверенные.

### Заменит ли это камеры?

Для вопроса «есть ли кто в комнате» возможно, после пилота. Распознавание людей остаётся за камерами, как в разборе [clearcam](/blog/clearcam-obnaruzhenie-lyudey-i-obektov-dlya-lyubyh-kamer-videonablyudeniya-2026/).

## Коротко о главном

RuView открыт под MIT и развивается, часть заявленного авторы сами помечают как непроверенное. Для присутствия в комнате измерения в открытом доступе противоречивы, для пульса и дыхания измерений с эталоном я не нашёл.

Если хотите проверить, годится ли Wi-Fi-датчик присутствия для вашего номера, кабинета или зала, настрою пилот с замерами и сравнением с обычным датчиком. Напишите мне в Telegram кодовое слово «ПРИСУТСТВИЕ».
