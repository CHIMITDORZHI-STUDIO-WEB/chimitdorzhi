# Образец Anthropic: ИИ-консультант для магазина и помощник владельца

>
  **Коротко.** Anthropic 2 сентября 2026 года выложила на GitHub образец ИИ-консультанта для магазина и ИИ-помощника для сотрудников: репозиторий anthropics/commerce-agents, лицензия Apache-2.0. Это демонстрационный код на вымышленной компании, и сама Anthropic его не поддерживает. Владельцу магазина полезны три идеи: два разных агента, запись в магазин только после подтверждения человеком и список действий, закрытых для агента. Оплаты, российских площадок и русского языка в описании нет, доступ к API из России уточняйте. Ниже чек-лист готовности каталога.

## Что это и что я проверил

Я сверил пересказы с первоисточниками 14 октября 2026 года: README, файл LICENSE и документы safety.md и backends.md из [репозитория](https://github.com/anthropics/commerce-agents), а также [анонс в блоге Anthropic](https://claude.com/blog/claude-for-commerce-agents) и [статью инженеров](https://claude.com/resources/articles/the-anatomy-of-effective-commerce-agents). Обе страницы датированы 2 сентября.

Подтверждено: лицензия Apache-2.0, правообладатель Anthropic PBC. Репозиторий создан 1 сентября, на ветке main один коммит от 31 августа, архивным он не помечен. На момент проверки 3233 звезды и 635 форков. В README сказано прямо: это референсная реализация, она не поддерживается и правки не принимает. Блог называет её blueprint, то есть образцом. Пост в GitHub Community с формулировкой «гайд по созданию ИИ-агентов для продаж» я не нашёл. Слово «гайд» в первоисточниках стоит в названии статьи инженеров «A guide to the anatomy of effective commerce agents».

Внутри два агента, у каждого по пять навыков. Покупательский: поиск, исследование покупки, планирование цели, поддержка клиентов, память. Для сотрудников: аналитика продаж, правка карточек, остатки, цены и акции, черновики кампаний. Есть четыре демо (розница, путешествия, телеком, билеты), запуск на Messages API, Agent SDK или Managed Agents и плагин commerce-builder для Claude Code. Все компании в репозитории вымышленные, заказов и списаний демо не делает. Общий обзор образца есть в статье про [торговых ИИ-агентов для магазина](/blog/torgovye-ii-agenty-dlya-magazina-2026/), здесь разговор про подготовку вашего магазина.

## Два агента с разными правами

Главная идея для владельца: покупатель и сотрудник получают разных агентов. Покупательский читает каталог, собирает корзину и показывает её, но в магазин ничего не записывает. Агент для сотрудников видит продажи и остатки и предлагает изменения. Личность определяет сервер: по документу safety.md ни в одном аргументе инструмента нет имени пользователя или номера магазина.

Один бот с общими правами на всех опасен. Клиент пишет «поставь мне скидку 30 процентов», а у бота тот же инструмент, что у менеджера. Как делить полномочия, я разбирал в статье про [границу автономности ИИ-агента](/blog/granica-avtonomnosti-ii-agenta-2026/).

## Как устроено подтверждение записей

Агент для сотрудников ничего не применяет сам. Инструменты записи создают черновик изменения, а применить его можно только по номеру, который ваше приложение пометило как одобренный. Согласие, набранное в чате, ничего не включает, предпросмотр тоже. Лимиты проверяются дважды, при создании черновика и при применении: число позиций, размер сдвига цены, глубина акции, размер пополнения, бюджет кампании, защищённые поля. Цифры лимитов в коде демонстрационные, подбирать их вам. Кто имеет право нажать «одобрить», решает ваш код: репозиторий проверяет лишь наличие отметки.

Похожий механизм в другом проекте разобран в статье про [Mensarium](/blog/mensarium-svoy-ii-agent-s-podtverzhdeniem-izmeneniy-self-hosted-2026/). У него лицензии нет, у образца Anthropic она есть.

## Чего в образце нет

Нет платежа: шаг оформления показывает корзину, а оплату ведёт ваше приложение. Нет готовых коннекторов: README прямо пишет «None ship». Из названных целей интеграции только зарубежные сервисы. Нет защиты входа: примеры принимают любого, авторизация, лимиты запросов и бизнес-правила остаются на вас. Российских площадок и 1С в README нет. Русский язык в README и анонсе не заявлен, как агент справится с ним, проверяйте на своих диалогах. Требуются Python 3.11 или новее и Node 22.

Доступ. Страница стран, где работает Anthropic, при проверке России не содержала. Как оплатить и подключить API из России, уточняйте.

## Что потребует доработки в российском магазине

**Каталог и 1С.** Бэкенд пишется вами: StorefrontBackend над каталогом, корзиной, заказами и политиками, MerchantBackend над аналитикой, остатками, ценами и кампаниями. Товары из 1С и сайта приводятся к записям образца, размеры и цвета оформляются как варианты. Если платформа не знает цифру, документ backends.md велит вернуть пустое значение и не подставлять ноль. Обмен сайта с 1С описан в статье про [интеграцию сайта с 1С](/blog/integraciya-sayta-s-1c-2026/).

**Оплата.** Остаётся в вашем эквайринге. Агент передаёт корзину.

**Персональные данные.** У покупательского агента есть память о клиенте. Длина фактов ограничена, значения, похожие на идентификаторы, по умолчанию отклоняются. Срок хранения, просмотр и удаление фактов и журналы запросов с корзиной остаются на вас. Если модель работает за границей, это передача данных за рубеж: уведомление Роскомнадзора по части 3 статьи 12 и локализация баз по части 5 статьи 18 закона 152-ФЗ. Детали с юристом.

## Чек-лист: готов ли каталог к ИИ-консультанту

- У каждого товара заполнены название, цена, остаток, категория и главные характеристики.

- Цена и остаток хранятся в одном источнике. Три таблицы с разными цифрами не подходят.

- Остатки обновляются с задержкой, которую вы готовы назвать покупателю.

- Размеры, цвета и комплектации заведены как варианты с отдельным артикулом и остатком.

- Политики возврата, доставки, гарантии и оплаты написаны текстом на странице. Скан или картинка без текста не подходят.

- Стоимость и сроки доставки считаются по правилам, которые можно записать.

- Статус заказа читается по его номеру.

- За каждое поле и каждую политику отвечает конкретный человек.

Моя прикидка, не норма: возьмите 50 случайных карточек. Если больше десяти без цены, остатка или характеристик, сначала чините данные. Правила возврата для сайта разобраны в статье про [возврат товара в интернет-магазине](/blog/vozvrat-tovara-internet-magazin-2026/).

## Что можно сделать уже сейчас

**Прогоните каталог по чек-листу.** Выгрузка в таблицу и час работы покажут, где дыры.

**Напишите список «чего агент не делает без вас».** Для начала: меняет цену, ставит скидку, оформляет возврат, называет срок доставки не из системы, отправляет рассылку, правит остаток, принимает оплату. По каждому пункту решите, кто подтверждает.

**Начните с чтения.** Авторы советуют так же: пилот покупательского агента реализует поиск и карточку товара, остальное отключено, а пилот агента для сотрудников начинается с методов чтения, записи отказывают.

**Соберите 30-50 настоящих вопросов клиентов с эталонными ответами.** Это ваш тест до запуска. Сколько стоит такой проект, разобрано в статье про [цену ИИ-агента для продаж](/blog/skolko-stoit-ai-agent-dlya-prodazh-2026/), собрать его под ключ я могу в рамках [разработки ИИ-агентов](/services/ai-agents/).

## Частые вопросы

### Можно ли поставить этот код в магазин как готовое решение?

Нет. Это референсная реализация на вымышленной компании без авторизации и платежа, которую Anthropic не поддерживает. Её берут как схему и каркас.

### Работает ли образец с русским языком и российскими площадками?

Подтверждения нет. В README и анонсе русский язык и российские площадки не упомянуты. Проверка на ваших диалогах обязательна.

### Можно ли использовать код в коммерческом проекте?

Лицензия Apache-2.0 разрешает коммерческое использование при соблюдении её условий. Юридические детали уточняйте у юриста.

## Коротко о главном

Образец Anthropic показывает рабочую схему: покупательский агент без права записи, агент для сотрудников с черновиками и подтверждением человеком, лимиты на каждое изменение. Оплату, авторизацию, 1С, русский язык и вопросы персональных данных придётся решать самому.
