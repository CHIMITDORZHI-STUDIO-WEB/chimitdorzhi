# ИИ-агент в браузере без скриншотов: 7 секунд и цена ошибки

>
  **Коротко.** Репозиторий browser-use/jev-ultrafast существует, лицензия MIT, создан 16.09.2026, в нём три коммита и один автор. Агент строит таблицу элементов страницы из DOM, без скриншотов в основном цикле, и за один запрос к внешней модели TypeSafe Jev выбирает действие и цель. Семь секунд это один запуск на Google Flights при замерах после открытия страницы. Модель размещена у TypeSafe, нужен её ключ, локального варианта в README нет. Агент работает в вашем профиле Chrome, поэтому ему нужен отдельный профиль и подтверждение шагов. Доступность из России уточняйте.

## Пост обещал семь секунд на поиск билета

В посте канала GitHub Radar от 21.09.2026 речь шла о быстром агенте, который управляет браузером по обычной команде. Название совпало с реальным репозиторием, отдельной ветки основного проекта browser-use это не оказалось: это самостоятельный репозиторий той же организации. Для офиса интересно другое: рутина в браузере (поиск, формы, проверка цен) выполняется быстрее человека, и вопрос только в цене ошибки.

## Что я проверил в репозитории

Смотрел 19.10.2026 через GitHub и API. Репозиторий [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast) с описанием «Fastest and cheapest web agent». Файл LICENSE: MIT, авторские права Browser Use. Создан 16.09.2026, около 23,3 тысячи звёзд, 1,7 тысячи форков, не архивирован, открытых обращений 204. Коммитов три, все от одного человека, последний в основной ветке от 18.09.2026. Проекту чуть больше месяца, а README и интерфейс на английском. Версия в pyproject 0.1.0, нужен Python 3.12 или новее. В README также стоит приглашение в список ожидания облачной версии Browser Use, то есть репозиторий отчасти витрина. Агента я не запускал, всё ниже по документации и коду.

## Как он видит страницу

Скриншоты в основном цикле не участвуют. Скрипт читает страницу одним вызовом браузера и собирает таблицу видимых элементов: номер, роль (кнопка, поле, список), название и текущее значение. Берутся обычные HTML и ARIA-элементы, полное дерево доступности не строится. В отчёте авторов сказано, что вариант с деревом доступности был медленнее и его заменили.

Дальше один запрос к модели Jev возвращает два ответа сразу: какую операцию выполнить (CLICK, TYPE_TEXT, SELECT, прокрутка, ожидание, DONE, BLOCKED) и какой элемент взять для каждой. Модель выбирает из готового списка и не пишет селекторы, координаты или код. Только когда нужно вписать текст, например название города, подключается вторая, небольшая языковая модель. Скриншоты включаются лишь в локальном инспекторе.

## Откуда семь секунд

Заявлено 7,073 секунды на поиск Zürich, London на Google Flights. Время считалось от первого решения после открытия главной страницы до принятого DONE. Открытие браузера, начальная навигация и итоговая независимая проверка в замер не вошли. Агент только находил варианты, билет не выбирал и не бронировал.

Авторы приводят шесть чередующихся запусков, по три на старую и новую версию. Медиана 9,450 секунды против 7,092, минус 25 процентов. Они же пишут, что это три повтора одной задачи на одном профиле и общей проверкой надёжности это не считается. Отдельные проверки: статья в Википедии за 2,798 секунды и локальная тестовая страница отеля за 1,896 секунды. Для вашего сайта закладывайте порядок «единицы и десятки секунд» и проверяйте сами.

Расход токенов в документации один: 90 558 входных и 6 325 выходных токенов на весь запуск на билетах. Два вызова текстовой модели обошлись в 0,00006272 доллара. Сколько списал сам TypeSafe, авторы не указали. Из вторичных источников известно о цене около 0,042 доллара за миллион входных токенов при бесплатном выводе. Первоисточник цены не нашёл, это не подтверждено. Условный пример при этой цене: запуск стоил бы менее полцента.

## Модели, ключи и куда уходит текст страницы

Jev размещён у TypeSafe. Код обращается к api.typesafe.ai/v1/systemone с ключом TYPESAFE_API_KEY, документация TypeSafe про размещение и регионы молчит. По вторичным источникам доступ в раннем режиме и сервис в США, это не проверено. Для текста по умолчанию стоит inception/mercury-2.5 через OpenRouter, также упомянуты Gemini, GLM и DeepSeek через совместимый адрес. Локальная модель в README не описана. Оплата и доступ из России: уточняйте.

Модели отправляется видимый текст страницы. Если в нём письма, цены или персональные данные, это вопрос коммерческой тайны и 152-ФЗ, как и у расширения из [разбора AIPex](/blog/aipex-rasshirenie-brauzera-delaet-rutinu-po-komandam-chto-porucit-i-gde-opasno-2026/).

## Быстрый агент и цена ошибки

Скорость работает в обе стороны: неверный клик тоже будет быстрым. Сами авторы пишут, что допустимое действие всё равно может быть неверным, а выбор DONE не доказывает успех, нужна отдельная проверка результата. Лимит запуска 60 действий и 120 запросов к модели.

С безопасностью так. Сервис инспектора слушает только 127.0.0.1 и проверяет заголовки и токен. Кнопка «Choose next» останавливает агента перед каждым действием, это готовое подтверждение шага. Но вкладки агента открываются в уже существующем профиле Chrome. Всё, во что вы там вошли, доступно агенту. Списка разрешённых сайтов в agent.py и browser.py я не нашёл, значит, ограничения по доменам придётся добавлять самим.

## Чего в проекте нет

Это MVP. Авторы прямо называют недоступными теневые деревья, фреймы, canvas, загрузку файлов, всплывающие вкладки и сложные клавиатурные виджеты. Часть личных кабинетов и порталов устроена именно так. Один автор, три коммита, месяц жизни, английский язык и привязка к платному сервису другой компании: это риск для процесса, от которого зависят деньги. Поэтому я бы использовал проект как образец устройства и стенд для проверки, а не как готовую основу рабочей системы.

## Что можно сделать уже сейчас

Выберите задачи только на чтение: проверка цен, поиск по каталогу, сверка наличия. Ошибка здесь стоит минуту времени, никакой заказ или запись не пострадают. Для форм и кабинетов с данными клиентов лучше другой путь: см. [роботов в браузере](/blog/rpa-robot-v-brauzere-2026/) и [запись задачи один раз](/blog/skill-recorder-zapis-zadachi-odin-raz-ii-agent-povtoryaet-rutinu-sotrudnika-2026/).

Заведите отдельный профиль Chrome без паролей, почты и банка, с тестовой учётной записью. Включите режим подтверждения каждого шага и сохраняйте журнал. Границу доверия я описывал в статье про [автономность агента](/blog/granica-avtonomnosti-ii-agenta-2026/).

Сделайте пробу на копии своей задачи, посчитайте долю верных запусков на двадцати повторах и время вместе с проверкой человеком. Настроить агента под вашу задачу с белым списком сайтов, ролью без прав на изменение и журналом могу в рамках [услуги по ИИ-агентам](/services/ai-agents/).

## Частые вопросы

### Бесплатно ли это?

Код бесплатный под MIT. Модель Jev оплачивается у TypeSafe (по вторичным данным), текстовая модель у выбранного провайдера. Итоговую стоимость запуска авторы не публиковали.

### Нужен ли интернет для самих моделей?

Да. Обе модели вызываются по сети, локального режима в README нет. Скриншоты в основном цикле не нужны.

### Можно ли доверить агенту оплату или удаление?

Я бы не доверял. Подтверждает человек, а оплата и удаление вообще вне зоны агента.

## Коротко о главном

Jev Ultrafast показывает, что агенту в браузере не нужны скриншоты: таблица элементов и один запрос на шаг дают единицы секунд на простой задаче. Это молодой проект с одним автором, внешней моделью и профилем без изоляции, поэтому пока он годится для проб на задачах только на чтение.
