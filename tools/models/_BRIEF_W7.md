# Волна 7 (22.09.2026): чем дополняем каталог

Читать вместе с `_BRIEF.md` (формат записи, правила фактов), `_BRIEF_FIELDS.md` (ru, industries,
ollama, cpu) и `_BRIEF_EN.md` (поле `en`). Здесь только отличия.

## Новые ключи modality
- `forensics` — детекция подделок: дипфейки на видео и фото, антиспуфинг лица и голоса,
  детекторы ИИ-сгенерированных картинок и текста, водяные знаки для ИИ-контента.

Для HR-моделей отдельного ключа нет: ставь `nlp`, `text` или `vlm` и обязательно `industries: ['hr', ...]`.

## Новое поле `quant` (у всех новых записей)
Сразу после `cpu`:

```js
quant: ['gguf', 'awq', 'int4'],   // пустой массив [] — если готовых квантованных сборок нет
```

Допустимые значения: `gguf` (есть GGUF-сборки, запускается в Ollama / llama.cpp),
`awq`, `gptq`, `int8`, `int4`, `fp8`, `mlx` (сборки под Apple Silicon).
Ставь только то, что видно у разработчика или в популярных репозиториях на Hugging Face.
Для генераторов картинок, видео и 3D обычно `[]`.

## Что важно помнить
- Аудитория — владельцы бизнеса, не инженеры. Просто, по-русски, без жаргона.
- Ничего не выдумывать: даты, размеры, лицензии — только с карточки HF / GitHub / официального блога.
- Нет открытых весов (только API) — в каталог не берём.
- Не уверен — `verified: false`, такие записи не публикуются.
- Для моделей клонирования голоса в summary обязательно: «только с согласия владельца голоса».
- Для медицинских: «не заменяет врача, решения принимает специалист».
- Для детекторов подделок в summary обязательна честная оговорка: детектор ошибается в обе стороны,
  его вывод — повод для проверки человеком, а не доказательство.
- Для HR-моделей в summary обязательна оговорка: решение о кандидате принимает человек,
  автоматический отбор без проверки использовать нельзя.
