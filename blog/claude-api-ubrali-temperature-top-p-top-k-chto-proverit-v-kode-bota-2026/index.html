Claude API убрал temperature: что проверить в коде бота

21 октября 2026 года Anthropic выпустила версию Claude API 2026-10-21, в которой запрос с temperature, top_p или top_k получает ошибку 400. Разбираю по документации, что именно изменилось, где искать параметры в коде и конструкторах и как проверить бота на 20 запросах до перехода. Доступ из России: уточняйте.

Claude APIAnthropicИИ-ботымиграция API
Коротко. 21 октября 2026 года Anthropic выпустила версию Claude API 2026-10-21, первую новую после 2023-06-01. Она включается заголовком anthropic-version или обновлением SDK до Python 2.0.0 и TypeScript 1.0.0. В ней удалены параметры temperature, top_p и top_k: запрос с любым из них, даже со значением по умолчанию, получает ошибку 400. Прежняя версия остаётся доступной, даты её отключения я не нашёл. Для бота: найти три параметра, прогнать 20 типовых запросов до и после, закрепить формат схемой, включить на одном боте. Доступ и оплата из России: уточняйте.

Проверить код бота и собрать тест перед переходом на новую версию Claude API

Что изменилось и что я проверил

Пост Machinelearning от 23 октября я сверил с документацией Anthropic: журнал изменений API, руководство по переходу и страница версий.

Подтверждено. В записи от 21 октября: вышла версия 2026-10-21, клиентские SDK отправляют её по умолчанию. Python SDK получил версию 2.0.0, TypeScript 1.0.0. Без SDK в запросе ставят заголовок anthropic-version: 2026-10-21. В истории версий до неё стоит только 2023-06-01, поэтому «впервые с 2023 года» верно.

Уточнение к пересказу. «Поправлены форматы сообщений» в документации означает два пункта. Блок document прямо в сообщении ассистента даёт 400. Текстовый блок с непустым citations в сообщении пользователя тоже даёт 400. Остальные удалённые поля относятся к Admin API и Analytics API, обычного бота они не касаются.

Что сломается и что останется

Ломается вызов с temperature, top_p или top_k: Messages API и пакетные запросы возвращают 400, на любой модели. В документации для этого случая назван только код 400, текст сообщения не приведён. Пишите в журнал поле request_id из тела ошибки, оно нужно для обращения в поддержку.

Без параметров модель сэмплирует по умолчанию, temperature 1,0, как и раньше. Модели Claude 4.7 и новее и так принимали только значения по умолчанию, у них ничего не меняется. Про Haiku 5.5 писал в разборе самой дешёвой модели. На Sonnet 4.6 и старше эффект от заниженной temperature пропадёт, и документация честно пишет: другой настройки взамен нет.

Ещё два пункта из руководства. SDK теперь шлёт ключ в заголовке Authorization: Bearer вместо X-Api-Key, API принимает оба. Это важно, если у вас шлюз или прокси читает старый заголовок. Изменений кэша промптов и инструментов в руководстве нет, другие страницы документации я не просматривал.

Где искать temperature в коде и панелях

В репозитории и конфигах: grep -rniE "temperature|top_p|top_k|topP|topK" . по коду, файлам окружения, YAML и JSON, выгрузкам сценариев n8n и Make.

Обёртки. В LangChain, LiteLLM и узлах n8n и Make температура часто стоит в настройках узла, и обёртка может слать её сама, даже если вы поле не трогали. Как они ведут себя с новой версией, я не проверял, смотрите на тестовой копии.

Панели конструкторов. Ищите ползунок «креативность» или «температура» в настройках ИИ-узла. Версию API при этом может выбирать сам конструктор: спросите у поддержки, когда он переходит.

Зависимости. Если в requirements.txt версия SDK не закреплена, обычное обновление принесёт 2.x с новой версией API по умолчанию. Закрепите версию до начала работ.

Ответы без temperature: как держать формат

Раньше низкая temperature сужала разброс ответов. Теперь разброс остаётся, и держать нужно структуру, а не дословный текст. Четыре меры.

  • Структурный вывод. В output_config.format передаёте JSON-схему, ответ приходит по ней. По документации функция вышла из беты и поддерживается в том числе на Sonnet 5.5 и Haiku 5.5. Ограничения: рекурсивные схемы и длины строк не поддерживаются, при refusal или max_tokens вывод может не совпасть со схемой, первый запрос с новой схемой медленнее, смена формата сбрасывает кэш промпта.
  • Проверка на вашей стороне. Валидатор схемы, значения из списка, длина.
  • Повтор. Если проверка не прошла, один-два повтора, потом запасной ответ вроде «передам менеджеру».
  • Стиль через промпт. Для Haiku 5.5 Anthropic прямо советует управлять поведением промптом: тон, лимит длины, два-три образца ответа. Параметр effort задаёт глубину размышлений и температуру не заменяет.

Тест на 20 запросах и порядок перехода

Возьмите из журнала бота 20 типовых запросов: 10 частых, 5 с ценой или таблицей, 3 с ответом «этого нет в базе», 2 провокации. Прогоните каждый по три раза на обеих версиях: 120 вызовов. Сравнивайте долю ответов, прошедших схему, совпадение ключевых полей между тремя прогонами (цена, дата, ссылка), длину ответа, токены из поля usage и число ошибок 400. Методика с золотым набором описана в статье про тест на 30 вопросах. Порог задайте до прогона, например: ни одной выдуманной цены.

Порядок. Сначала копия бота с отдельным ключом и тестовыми данными. Три параметра уберите ещё на 2023-06-01, версию меняйте потом: так ошибки не смешаются. Дальше пилот на одном боте, мониторинг ошибок 400 и повторов, откат на прежнюю версию. Про откат: смена версии у провайдера.

Календарь, предложение от меня, срока от Anthropic нет. Сегодня, 24 октября, отправьте подрядчику вопросы. До 31 октября он письменно подтверждает, где в коде параметры, какая версия SDK и кто её обновляет. Первая неделя ноября тест, вторая пилот. Остальные боты позже.

Чек-лист из семи пунктов:

  1. Поиск трёх параметров по коду и конфигам.
  2. Список обёрток и панелей с ползунком температуры.
  3. Закреплённая версия SDK и ответ, кто её обновляет.
  4. Удаление параметров на старой версии, проверка.
  5. Схема ответа и валидатор на выходе.
  6. Тест 20 запросов по три прогона до и после.
  7. Пилот на одном боте, мониторинг, готовый откат.

Что не подтверждено и что с доступом

Не нашёл: срок поддержки версии 2023-06-01, текст сообщения об ошибке для температуры, обещание Anthropic обновлять API регулярно. На странице версий сказано лишь, что она рекомендует последнюю. Как ведут себя LangChain, LiteLLM, n8n и Make с новой версией, не проверял.

Доступ. На странице поддерживаемых стран на 24 октября России нет. Как сейчас обстоят оплата и доступ из России, уточняйте, способов не называю. Данные клиентов в запросе к модели это передача за рубеж, см. 152-ФЗ для чат-ботов. Российские модели как запасной вариант: сравнение GigaChat, YandexGPT и ChatGPT.

Частые вопросы

Надо ли переходить срочно?

Срока отключения 2023-06-01 я не нашёл, бот без обновлений работает. Риск в другом: обновление SDK до 2.x само включит новую версию.

Можно ли оставить temperature на старой версии?

На 2023-06-01 для моделей, которые принимают другие значения, можно. Новые модели, например Haiku 5.5, уже отвечают 400 на такие значения, поэтому смена модели ломает тот же код.

Коротко о главном

Версия API 2026-10-21 удаляет temperature, top_p и top_k, ответ на них 400. Старая версия остаётся, срока отключения не нашёл. Формат ответа теперь держат схемой, проверкой и повтором.
