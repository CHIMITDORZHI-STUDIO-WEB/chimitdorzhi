Backend Skills: бэкенд от ИИ без сюрпризов в проде, что требовать

Backend Skills: три навыка для ИИ-агентов, которые должны остановить бэкенд, проходящий демо и ломающийся в проде. Я прочитал навыки и тест: как считали 25 против 2, кто судья, что замер сделали сами авторы. В конце наш чек-лист приёмки.

Backend SkillsбэкендИИ-агентыприёмка кода
Коротко. Backend Skills (репозиторий globalmpc/backendskills, лицензия MIT) это три текстовых навыка для ИИ-агентов: права доступа, целостность данных и денег, безопасные миграции базы. Авторы заявляют 25 критических ошибок в 150 запусках без навыков и 2 из 150 с ними. Замер сделали сами авторы, на двух моделях Claude и одном учебном приложении, и почти весь разрыв дают две задачи из пятнадцати. Проекту две недели, звёзд 60. Данные на 18.11.2026, сами навыки с агентом я не запускал.

Сайт работает на показе и ломается в первую неделю

Вы заказали магазин или бота с оплатой. На показе всё красиво: заказ создаётся, оплата проходит. Через неделю покупатель дважды жмёт «Оплатить» и платит два раза. Другой меняет номер заказа в адресной строке и видит чужие данные. Третий подбирает пароль к чужому аккаунту, и никто его не останавливает. Это обычные ошибки кода, который ИИ-агент написал по короткой задаче.

Исполнитель, который работает с агентами, получает такой код каждый день. Общую проверку кода перед сдачей я разбирал в статье про no-mistakes. Здесь речь про правила именно для бэкенда.

Что в репозитории и как это подключить

Я склонировал репозиторий и прочитал все три навыка, около тысячи слов каждый. Примеры на TypeScript и Postgres, для MySQL есть пометки.

  • api-endpoint. Запросы к данным ограничены вошедшим пользователем, у вебхука проверяется подпись, неверные данные дают 4xx, вход и коды ограничены по числу попыток, в ответ идут только нужные поля.
  • data-integrity. Проверка остатка входит в запрос на запись, уникальность держит ограничение базы, внешние вызовы не лежат внутри транзакции, списание и возврат получают ключ идемпотентности, повторный вебхук не откатывает статус.
  • db-migration. Переименование в два выпуска, индексы без блокировки записи, откат каждой миграции с прогоном вверх, вниз и снова вверх.

Лицензия MIT, файл LICENSE на месте. Репозиторий создан 05.11.2026, в нём три коммита от одного аккаунта, последний от 18.11.2026, релизов нет, открытых обращений ноль. В README проект ведёт Global MPC (Mineral Project Coin), а профиль организации на GitHub говорит об открытом коде вокруг токена на BNB Smart Chain. Что это за компания, я не выяснял.

Подключение по README: для Claude Code команда npx skills add globalmpc/backendskills, для Codex дописать в AGENTS.md файл dist/AGENTS.md, для Cursor скопировать dist/cursor в .cursor/rules/. Я этого не запускал. Навыки это текстовые файлы, которые агент читает перед работой, кода они не исполняют.

Что считали критической ошибкой и как мерили

Я прочитал папку bench. Пятнадцать задач на учебном приложении, небольшом магазине на Node, Express и Postgres. Задачи короткие: «добавь вход по паролю», «переименуй колонку», «обработай вебхук оплаты». О защите в задаче ни слова. Агент (Claude Code 2.1.318) работал с чистыми настройками, потом скрытые тесты, которых он не видел, проверяли результат: двадцать покупателей на пять товаров одновременно, чтение чужого заказа, старая версия приложения на новой схеме во время выкладки.

Критическая ошибка это проваленная проверка безопасности: утечка, неограниченный подбор пароля, продажа сверх остатка, двойное списание, взаимная блокировка, миграция, ломающая живую базу. Командные договорённости считаются отдельно. Судья здесь автоматические тесты, другой модели в роли судьи нет. Модели Haiku 5.5 и Sonnet 5.5, по пять запусков на задачу, по 150 запусков в каждом режиме. Я пересчитал своей короткой программой файл runs.jsonl: Haiku 12 из 75 против 2 из 75, Sonnet 13 из 75 против 0 из 75, как в README. Сами запуски агента я не повторял: авторы оценивают полный прогон примерно в 95 долларов.

Что цифры показывают и чего нет

  • Из 25 ошибок без навыков 20 дают две задачи: ограничение попыток входа и переименование колонки. Десять задач из пятнадцати не дали критических ошибок ни с навыками, ни без них.
  • Тесты и навыки написала одна команда, примеры у них общие: в навыке разобраны 50 параллельных попыток пароля, столько же в тесте. На чужих задачах навык не испытан.
  • У Haiku на задаче с вебхуком стало хуже, 1 из 5 против 2 из 5. Авторы пишут об этом сами.
  • С навыками агент тратит больше: 0,11 доллара за запуск против 0,06 и 23 хода против 14, по данным авторов.
  • Измерены только модели Claude. Для Codex и Cursor есть файлы правил, цифр по ним нет.

Независимого повтора я не нашёл. Зато в первый день сторонний читатель написал о трёх ошибках в примерах: окно блокировки входа не истекало, успешное списание могло считаться неудачным. Авторы поправили текст, в версии от 18.11.2026 этих ошибок я не вижу.

Чего в навыках нет и что они не заменяют

Я искал по тексту: слов про секреты, внедрение SQL, CORS и журналы там нет. Запросы в примерах параметризованы, но отдельного правила нет. Про ключи и данные клиентов в коде читайте разбор DevProjex. Навыки не заменяют ревью кода человеком, тесты вашего приложения и нагрузочную проверку: двадцать параллельных запросов в учебном тесте это не пиковая нагрузка. Они не знают вашей схемы и вашего платёжного провайдера.

Чек-лист приёмки бэкенда

Список наш, авторы его не составляли. Шесть пунктов взяты из содержимого навыков, два последних добавил я.

  1. Два тестовых пользователя: один не читает и не меняет данные другого, подмена номера в адресе даёт 404.
  2. Вход и отправка кодов ограничены по числу попыток, счётчик общий для всех серверов.
  3. Двойной клик и повтор вебхука дают одно списание, подпись проверяется, порядок событий статус не откатывает.
  4. Двадцать параллельных заказов на малый остаток: остаток не уходит в минус, в базе стоит ограничение.
  5. Миграции: переименование в два выпуска, индексы без блокировки, откат проверен.
  6. Ошибочные данные дают 4xx, в ответах нет лишних полей, у списков есть предел страницы.
  7. Ключи вне репозитория, запросы параметризованы, копия базы проверена восстановлением.
  8. Исполнитель показывает вывод тестов и подтверждает, что код смотрел человек.

Что можно сделать уже сейчас

  1. Спросите исполнителя, какие правила для бэкенда он даёт агенту, и попросите показать их.
  2. Впишите пункты 1–5 чек-листа в договор как условие приёмки.
  3. Требуйте вывод тестов на параллельные запросы и повтор вебхука вместо слов «проверили».
  4. Если сервис уже работает, закажите проверку до запуска оплаты: я делаю технический аудит, а разработку с такой приёмкой веду в рамках услуги сайты и веб-приложения. Стоимость на странице цен.

Частые вопросы

Если подключить навыки, ошибок не будет?

Будут. По данным самих авторов, в режиме с навыками остались 2 критические ошибки на 150 запусков, а проверялись пятнадцать типовых задач. Ваш проект шире.

Нужны ли они сайту-визитке?

Нет. Навыки про бэкенд с пользователями, деньгами и базой.

Коротко о главном

Backend Skills это три короткие инструкции под MIT, которые в замере самих авторов убрали почти все критические ошибки на двух моделях Claude. Проект молодой, замер не независимый, секреты и внедрение SQL не покрыты. Полезнее всего он как готовый список требований к исполнителю.
