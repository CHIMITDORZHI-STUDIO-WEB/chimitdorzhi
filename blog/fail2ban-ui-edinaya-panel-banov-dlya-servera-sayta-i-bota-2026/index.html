Fail2Ban UI: одна панель банов для сервера, сайта и бота

Fail2Ban UI собирает управление банами нескольких серверов в одну панель: поиск IP, разблокировка без SSH, правка jail, уведомления. Разобрал по репозиторию и документации, как панель связывается с серверами, чем закрыть вход (без OIDC входа нет вообще) и что уходит наружу. В конце чек-лист на вечер и пилот на одном сервере.

Fail2Banбезопасность сервераVPSopen source
Коротко. Fail2Ban читает логи сервера и банит адреса, которые подбирают пароли. Fail2Ban UI (репозиторий swissmakers/fail2ban-ui, лицензия AGPL-3.0) добавляет веб-панель для одного или нескольких серверов: баны, поиск и разблокировка адреса, правка jail, уведомления. Проект живой, релиз v1.6.1 вышел 11.10.2026. Риск сидит в самой панели: без OIDC входа в неё нет вообще, а через неё можно ослабить защиту. Держите её на 127.0.0.1 и открывайте через SSH-туннель или VPN.

Кибербезопасность: защита сервера, панелей и доступов

Кто стучится на ваш сервер

Вы поднимаете VPS под сайт, бота или CRM, и через несколько часов в журнале SSH появляются попытки войти под root, admin, ubuntu. Это автоматические сканеры: они перебирают адреса подряд и вас не выбирали. На сайт так же приходят запросы на /wp-login.php и /.env, даже если у вас нет WordPress.

Проверить можно за минуту: journalctl -u ssh --since yesterday | grep -c "Failed password". Название юнита (ssh или sshd) зависит от дистрибутива. Про ошибки первой недели я писал в статье про свой VPS для разработчика.

Что делает Fail2Ban и что за панель

По README репозитория fail2ban/fail2ban, это демон, который читает логи и банит адреса с большим числом неудачных входов, меняя правила фаервола на заданное время. Лицензия GPL версии 2 или новее. В jail.conf из репозитория по умолчанию bantime 10 минут, findtime 10 минут, maxretry 5. В вашем дистрибутиве цифры могут отличаться.

README сам оговаривает: Fail2Ban уменьшает число неудачных входов, но не убирает риск слабой аутентификации, нужны ключи или двухфакторка. Обновления системы, фаервол с закрытыми портами и WAF перед сайтом он тоже не заменяет. Порядок первичной настройки описан в статье как настроить VPS с нуля.

Панель проверял 18.10.2026. Репозиторий swissmakers/fail2ban-ui описан как платформа для управления Fail2Ban на одном или нескольких Linux-хостах. Файл LICENSE содержит текст GNU AGPL v3. Язык Go, создан 25.01.2025, около 373 звёзд, не архивирован, открытых issue три. Последний коммит от 11.10.2026, релизы v1.6.0 (8 октября) и v1.6.1 (11 октября). Поддерживает компания Swissmakers GmbH. По README, платной версии нет, а делают проект в свободное время.

Как панель добирается до серверов

Решения о банах по-прежнему принимает демон на каждом сервере. Панель управляет им через один из трёх коннекторов. Локальный работает через сокет Fail2Ban. SSH-коннектор ходит по ключу и вызывает fail2ban-client на удалённом хосте. Агентный ставит на хост HTTP-агента из отдельного репозитория fail2ban-ui-agent.

Обратный путь: на каждом хосте появляется действие Fail2Ban, которое через curl сообщает панели о каждом бане и разбане. Адреса /api/ban и /api/unban открыты без входа и защищены общим секретом. Очереди на хосте нет, при долгом простое панели события могут потеряться, это написано в документации.

Ставится в контейнере Docker или Podman (образ swissmakers/fail2ban-ui на Docker Hub и в ghcr.io) либо службой systemd, для которой бинарник собирают из исходников. Готовых пакетов в документации не нашёл. В примере из README контейнер запускается с --network=host, а каталог /etc/fail2ban с записью и сокет Fail2Ban монтируются внутрь.

Панель как новая дверь

Для входа поддерживается OIDC: Keycloak, Authentik и Pocket-ID. Локальных пользователей и собственной двухфакторки в документации не нашёл, двухфакторную защиту даёт ваш провайдер OIDC. Когда OIDC выключен, проверка в файле pkg/web/auth.go пропускает любой запрос. Порт по умолчанию 8080, адрес по умолчанию 0.0.0.0. Значит, пример из README на публичном VPS даёт панель без пароля, доступную всем по http.

Документация предупреждает: не выставлять в интернет, использовать VPN, прокси со списком адресов и OIDC. Роли: администратор и поддержка (просмотр, ручной бан и разбан). Без заданных ролей любой вошедший через OIDC получает полный доступ. Сессия в зашифрованной куке, по умолчанию час, отозвать её раньше срока нельзя.

Попавший в панель может править jail, перезапускать Fail2Ban и снимать баны. Для SSH-коннектора документация просит sudo минимум на fail2ban-client. По справке fail2ban-client умеет задавать команду actionban для действия jail, а выполняет её Fail2Ban от root. Это моя оценка, проект такого не заявляет: доступ панели к хостам стоит считать близким к root. Единый защищённый вход с двухфакторкой я разбирал в статье про шлюз Cosmos.

Данные. События лежат в SQLite, срок хранения задаётся в днях, ноль означает «навсегда». В записях IP, jail, имя хоста и строки логов, а в логах бывают логины и почта. Встроенная геолокация ходит на ip-api.com: каждый обогащаемый адрес уходит стороннему сервису, бесплатный тариф работает по http без шифрования. Вместо него можно взять локальную базу MaxMind GeoLite2. Запросы к AlienVault OTX и AbuseIPDB выключены по умолчанию. Считать ли IP персональными данными, решает юрист.

Чего панель не умеет и как не забанить себя

Только Linux. Постоянные блокировки на периметре работают лишь с MikroTik, pfSense, OPNsense и UniFi. Замены WAF и фаервола нет. Уведомления: почта (SMTP), webhook и Elasticsearch. Webhook подходит для ntfy, Slack, Mattermost и Gotify. Telegram отдельным каналом в списке не нашёл, через промежуточный сервис возможно, не проверял.

Чтобы не забанить себя и клиентов, внесите в ignoreip свой адрес и офисный статический IP. В jail.conf параметр ignoreself включён по умолчанию, пример ignoreip закомментирован. С v1.6.1 исключения можно задавать для отдельного jail. У мобильных операторов один внешний адрес нередко делят многие абоненты, и бан за ошибку одного отрежет остальных. Для входа клиентов в CRM ставьте maxretry мягче, чем для SSH.

Условный пример. Три VPS: сайт, бот и CRM, клиент пишет «CRM не открывается». Без панели: зайти по SSH, перебрать jail, найти адрес. С панелью: поиск адреса по всем серверам и разбан в нужном jail. Допущение: десять минут против одной-двух, это прикидка, не замер. Сначала убедитесь, что адрес его.

Что сделать за вечер

Проверьте fail2ban-client status: служба запущена, jail для sshd включён. Переведите вход на ключи, выключите пароль, свой адрес внесите в ignoreip.

Пилот на одном сервере. Поставьте контейнер с локальным коннектором, закрепите версию тегом v1.6.1 вместо latest, задайте BIND_ADDRESS=127.0.0.1 и заходите через туннель ssh -L 8080:127.0.0.1:8080. Неделю смотрите, какие адреса банятся.

Второй сервер подключайте после того, как решили, чем закрываете панель: VPN, прокси со списком адресов или OIDC. Для SSH-коннектора заведите отдельную учётку. Поставить панель, настроить доступ и белые списки могу в рамках услуги по кибербезопасности.

Частые вопросы

Нужен ли Fail2Ban, если есть фаервол?

Нужен. Фаервол закрывает лишние порты, а Fail2Ban реагирует на подбор пароля на открытых, например на SSH.

Что будет, если панель упадёт?

Fail2Ban продолжит банить: по README решения принимает демон на хосте. События о банах за время простоя могут не дойти до панели.

Можно ли открыть панель в интернет за паролем на прокси?

Документация советует VPN, список адресов и OIDC. Если ставите пароль на прокси, исключите из него /api/ban и /api/unban для удалённых хостов. Это мой вывод из описания, на стенде не проверял.

Коротко о главном

Fail2Ban закрывает подбор паролей по логам, а Fail2Ban UI под AGPL-3.0 собирает управление банами нескольких серверов в одном окне. Панель управляет защитой, поэтому закрывайте её раньше, чем начнёте использовать: loopback, туннель или VPN, OIDC, отдельная SSH-учётка.
