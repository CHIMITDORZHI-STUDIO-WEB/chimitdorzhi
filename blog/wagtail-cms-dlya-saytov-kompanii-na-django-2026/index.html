Wagtail: CMS на Django для сайта компании без плагинов

Wagtail это открытая CMS на Django (BSD-3, около 20,5 тысячи звёзд, релиз 8.0 от 25 августа 2026). Редакторы работают в удобной админке с правами и согласованием, разработчик держит структуру сайта в коде. Разбираем, когда это лучше WordPress и конструктора и где без Python не обойтись.

WagtailCMSDjangoсайт компании
Коротко. Wagtail это система управления сайтом на Django с лицензией BSD-3, около 20,5 тысячи звёзд на GitHub и свежим релизом 8.0 от 25 августа 2026 года. Редактор получает удобную админку с черновиками, правами и согласованием публикации. Разработчик задаёт структуру страниц в коде и не зависит от плагинов. Подписки нет, платите только за сервер и работу специалиста. Условие одно: для запуска нужен человек, который знает Python и Django.

Разработка сайтов под ключ

Сайт, который боятся трогать

Знакомая картина. Сайт компании сделан на WordPress лет пять назад. Для форм стоит один плагин, для поиска другой, для многоязычности третий. Раз в полгода что-то обновляется, и что-то ломается. Редактор боится нажать лишнюю кнопку, потому что прошлый раз после этого пропал блок на главной. Второй вариант: сайт на конструкторе. Правки делаются легко, но платить приходится каждый месяц, а когда нужна нестандартная логика, упираетесь в потолок. Про сравнение этих путей мы уже писали: Тильда или WordPress и Tilda против кастомной разработки.

Wagtail стоит между ними. Это готовая система управления контентом, но каркас страниц пишется в коде, поэтому на сайте нет ничего лишнего.

Что такое Wagtail

Wagtail развивается открыто, код лежит в репозитории wagtail/wagtail. Лицензия BSD 3-Clause: можно использовать в коммерческом проекте и в закрытом коде, платить за лицензию не нужно. На момент проверки у проекта около 20,5 тысячи звёзд и около 4,6 тысячи форков. Последний коммит был 1 октября 2026 года, то есть проект живой. По README проект заявляет быстрый интерфейс для авторов, несколько сайтов и языков, встроенный поиск через Elasticsearch или PostgreSQL и режим без фронтенда через API. В списке пользователей указаны Mozilla, MIT и британская служба NHS. Это самоописание проекта, мы его не перепроверяли.

Что видит редактор

Редактору не нужно знать, что такое Django. Он работает с деревом страниц: добавляет раздел, пишет текст, вставляет картинки и блоки, которые заранее подготовил разработчик. Страница из блоков (в Wagtail это называется StreamField) даёт свободу в тексте, но не позволяет сломать вёрстку. Что подтверждается документацией:

  • Права задаются на любом уровне дерева страниц и наследуются вниз. Отдельные права есть на создание, редактирование, публикацию и блокировку страниц. Редактор может править, но не публиковать.
  • Для картинок и документов есть коллекции со своими правами. Например, бухгалтерия видит только свою папку.
  • Согласование публикации встроено. Базовая задача называется GroupApprovalTask: любой участник выбранной группы может утвердить или отклонить страницу. При необходимости разработчик пишет свои шаги.
  • Отложенная публикация и снятие с публикации по дате описаны в документации.
  • Конструктор форм входит в состав. Редактор собирает контактную форму прямо в админке, получает письма и смотрит заявки там же.
  • В репозитории есть файл русской локализации админки.

Что получает разработчик

Модели страниц это обычные классы Django. Хотите страницу услуги с тремя полями и блоком отзывов, пишете класс, и редактор видит именно эти поля. Всё хранится в вашей базе: поддерживаются PostgreSQL, MySQL, MariaDB и SQLite. По README нужен Python 3.11–3.14 и Django 5.2, 6.0 или 6.1. Многоязычность устроена так: на каждый язык отдельное дерево страниц, а связь между переводами ведётся автоматически. Если сайтов несколько, у каждого может быть своя главная для разных языков. Для удобного перевода есть сторонний пакет Wagtail Localize. Если фронтенд делается отдельно, Wagtail отдаёт контент по API. В версии 8.0 появился предварительный REST API третьей версии на Django Ninja, он умеет не только читать, но и создавать, публиковать и менять контент. Пока это превью, на него лучше не опираться в боевом проекте без запаса времени.

Чем отличается от Payload и Strapi

Мы разбирали Payload CMS, и логика там похожая: свой сайт, своя админка, без платы за место. Разница в стеке. Payload живёт внутри приложения на Next.js и TypeScript. Wagtail это Python и Django. Если в команде или у подрядчика уже пишут на Python, выбор очевиден. Если сайт и так делается на React и Next.js, Payload будет естественнее. В Strapi контент это записи с API. В Wagtail страницы образуют дерево с адресами, правами и согласованием. Для корпоративного сайта с разделами и редакторами такая модель удобнее. Для набора данных под мобильное приложение подойдёт Strapi, он как раз про это.

Где Wagtail не подойдёт

  • Без разработчика не обойтись. Установить Wagtail как приложение в один клик нельзя, это фреймворк. Нужен специалист на Python и Django, и позже тот, кто будет обновлять версии и следить за безопасностью.
  • Готовых тем и каталога плагинов, как у WordPress, нет. Дизайн рисуется и верстается под вас. Для одностраничного лендинга на неделю это перебор, туда лучше конструктор.
  • Про версии. Версия 8.0 не является долгой поддержкой. Статус LTS у 7.4, выпущенной 4 мая 2026 года, поддержка по плану до 2 ноября 2027 года. Для спокойного сайта разумнее брать LTS.
  • Админка переведена на русский не везде одинаково, мелкие надписи могут остаться английскими. Полноту перевода мы не измеряли.
  • Проект зарубежный, у него открыто больше тысячи задач. Это нормально для такого размера, но срочной правки в ядре придётся ждать или делать самим.

Что можно сделать уже сейчас

  1. Выпишите, что редакторы меняют на сайте каждый месяц: новости, цены, акции, вакансии. Это и есть структура будущей админки.
  2. Посчитайте, сколько платите за конструктор и плагины в год и сколько часов уходит на борьбу с обновлениями. Это прикидка, но она показывает, окупается ли переезд.
  3. Разверните демо у себя: pip install wagtail, команда wagtail start, и через полчаса вы увидите админку. Достаточно, чтобы редактор сказал, удобно ли ему.
  4. Определите, нужны ли согласование, несколько языков или несколько сайтов. Если да, Wagtail закрывает это из коробки, а на WordPress это обычно набор плагинов.

Мы разворачиваем и делаем сайт под ключ

Мы делаем сайты на Wagtail под ключ: структура страниц под ваши задачи, дизайн, права для команды, форма заявок, перенос контента со старого сайта, развёртывание на вашем сервере и обучение редакторов. О том, как мы подходим к веб-разработке, написано на странице разработки сайтов. Если Wagtail не подойдёт, скажем прямо и предложим другой вариант, например Payload или конструктор.

Частые вопросы

Это бесплатно?

Лицензия BSD-3 разрешает использовать код бесплатно, в том числе в коммерческом проекте. Платить придётся за хостинг и за работу разработчика. Подписки на систему нет.

Заменит ли Wagtail WordPress?

Для сайта компании с постоянными правками да. Для блога, который ведёт один человек и которому нужна тысяча готовых плагинов, WordPress проще. Выбор зависит от того, есть ли у вас разработчик.

Нужен ли отдельный фронтенд?

Нет. Wagtail сам отдаёт страницы через шаблоны Django. Отдельный фронтенд на React или Vue нужен, только если вы хотите именно такую архитектуру, тогда используется API.

Коротко о главном

Wagtail подходит компаниям, у которых сайт живёт и меняется: редакторы работают в удобной админке, а разработчик держит структуру под контролем. Минус один и честный: без специалиста по Python и Django это не заведётся.
